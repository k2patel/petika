# Synthetic local-unlock experiment

Standalone capability probes for the [device-key proposal](../../docs/research/multi-device-biometric-keys.md).
No production imports, account credentials, vault inputs, telemetry, dependencies on
the Petika server, or production-format changes. Generated secrets stay in memory;
only status is printed. This does not implement multiple identities per account.

## Apple

Requires macOS and Apple's Swift SDK with CryptoKit/Security/LocalAuthentication.

```sh
swiftc experiments/biometric-unlock/apple.swift -o /tmp/petika-apple-probe
/tmp/petika-apple-probe
/tmp/petika-apple-probe --software-test
# Interactive: creates an ephemeral hardware key and requests biometric verification.
/tmp/petika-apple-probe --hardware-roundtrip
```

The default command checks capabilities without authentication or creating keys.
The interactive command seals random bytes to an enclave P-256 public key using
ephemeral ECDH, HKDF-SHA256 and AES-GCM. Recipient and ephemeral public keys bind
the KDF and AEAD. It reconstructs the enclave key from its opaque hardware-wrapped
representation in memory and requires the protected ECDH operation to open the data.
Access control is `whenUnlockedThisDeviceOnly`, `privateKeyUsage`, `biometryCurrentSet`;
there is no passcode or software-key fallback. A fresh LAContext has reuse disabled.
No permanent Keychain entry or key blob is saved. Software tests never use the enclave.

Capability queries can fail under a process sandbox even on supported hardware.
Run the probe in a normal terminal to distinguish access restrictions from missing
hardware. Successful round-trip alone does not validate lockout, enrollment changes,
reboot, recovery, app entitlements, or iOS. No iOS signing account is needed here.

## Browser

```sh
node --test experiments/biometric-unlock/browser/probe.test.mjs
python3 -m http.server 8769 --bind 127.0.0.1 --directory experiments/biometric-unlock/browser
```

Open `http://localhost:8769`. Create a clearly labeled synthetic passkey, then seal
and reopen generated bytes in two separate user-verification ceremonies. A PRF result
derives a non-exportable WebCrypto AES-GCM key through HKDF-SHA256 with a random salt
and experiment-specific label. Each wrapper uses a random nonce and binds the credential
ID as authenticated data. Missing PRF output, cancellation and missing user-verification
flags fail closed. PRF bytes and plaintext buffers are cleared where accessible; JS
and CryptoKit copies/garbage collection mean this is not a secure-memory guarantee.

The page has no fetch, storage, analytics or remote assets, and CSP disallows connections.
Reset, backgrounding and navigation abort pending ceremonies and forget page state.
The authenticator may retain/sync the test credential; remove **Petika synthetic probe**
from it afterward. The page cannot delete that credential. Browser verification can
use a PIN; it is not proof of biometrics, hardware provenance or one physical device.
This is local encryption experimentation, not server-side WebAuthn authentication:
there is no relying-party registration, attestation/signature verifier or account session.

The Node tests inject a mock credential interface and use real WebCrypto. They cover
wrapper tampering, wrong keys/binding, missing PRF, missing verification, substituted
credentials, cancellation and late response rejection. Mocks are not hardware evidence.

With the repository's pinned Playwright 1.60.0 and Chromium installed, run
`python experiments/biometric-unlock/test_browser.py` for the real browser test using
an ephemeral **virtual** CTAP2.1 PRF authenticator. It starts its own loopback server,
checks seal/reopen, cancellation, unsupported PRF, empty web storage and static-only
requests, and saves desktop/mobile screenshots under ignored `output/biometric-unlock/`.

## Evidence and remaining work

See [recorded results](../../docs/testing/biometric-unlock-2026-10-31.json).
The physical Mac Touch ID round-trip passed with user approval on 2026-10-31;
this is one successful hardware operation, not full lifecycle validation.
Hardware lifecycle tests, real browser/authenticator PRF tests, two independent device
identities, Standard/Hybrid packages, enrollment/revocation/recovery and protocol review
remain open. A classical outer wrapper adds a classical access path to any Hybrid
secret; this experiment makes no post-quantum or FIPS validation claim.

API references: [Apple enclave key agreement](https://developer.apple.com/documentation/cryptokit/secureenclave/p256/keyagreement/privatekey),
[biometric enrollment binding](https://developer.apple.com/documentation/security/secaccesscontrolcreateflags/biometrycurrentset),
[W3C PRF explainer](https://github.com/w3c/webauthn/blob/main/explainers/prf-extension.md).
