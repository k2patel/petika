## Administrator Git settings and clearer introduction

Added **Settings → Git repository** and a shortcut under **Sync & backup**. Administrators
can save a private HTTPS/SSH remote, encrypted credentials and a manual, after-change or
periodic schedule. Connection tests, queued/running state, verified pushes and actionable
errors are shown separately. Changing the destination requires fresh credentials and
saving requires the current account password. Credentials are never returned to the UI.

The new worker performs fast-forward-only pushes and verifies remote refs. API data is
retained on failures. The updated legacy sidecar yields after the first UI settings save;
existing credentials are not silently imported. See the
[administrator setup guide](../administrator-guide.md#configure-encrypted-git-copies-in-the-web-ui).
This bounded addition does not change the established roadmap order or the completed
R01–R08 recovery milestone.

The README heading, browser title and sign-in introduction explicitly identify Petika as
a self-hosted password manager. GitHub description/topics now describe actual features
(password management, TOTP, Rust CLI, experimental browser autofill and encrypted Git copies)
without claiming a search ranking, an audited release or compliance certification.

Validation: real local Git/API tests cover HTTPS/SSH credential isolation, administrator
access, encrypted settings, restart, verified pushes and remote-ahead rejection. Browser
QA covers guided setup, secret fields staying blank, unsaved-change controls and mobile
layout. Hosted-provider TLS/SSH integration is not established by the local transport
adapter. Runtime/deployment evidence for this follow-up is recorded after rollout.
