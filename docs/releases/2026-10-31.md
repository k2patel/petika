# October 31, 2026 — retained-authority identity replacement

Experimental entry collections can now rotate after their authority account enrolls
a replacement identity. Previously, changing that identity blocked further rotation.
The retained old signing key authorizes a checkpoint signed by the newly enrolled key;
the CLI requires independent confirmation of the replacement fingerprint. The server
checks the same account, increasing identity version, current enrollment, edit access,
membership generation and exact recipient roster before journal publication.

`entries rotate --replacement-identity ... --replacement-fingerprint ...` stages a
fresh root and encrypted candidate. Review and explicit submission use the new
authority bundle. Names, fields, TOTP and the delivery profile are preserved. Exact
retries retain drafts and reconcile receipts; failures do not reset client trust.
See the [workflow](../research/entry-history-transport.md#replace-the-same-accounts-authority-identity).

Local validation passed:

- Nine core checkpoint/epoch transaction tests, including both signature checks.
- Ten server epoch-journal tests, including authorization and publication failures.
- Two CLI rotation scenarios, each exercising both recovery policies, lost
  acknowledgements, cache conflicts and exact retry.
- Full-server/client-kit authority replacement recovery in Standard and experimental
  Hybrid; new identities decrypt and retired identities fail at the exact new pin.
- Default and experimental Clippy, formatting and staged secret scanning.

This closes the retained-key authority replacement item in the broader backlog.
R01–R08 remain 8/8 complete. It does not recover a lost authority signing key, delegate
authority to another account, enroll multiple device identities, or add biometric
unlock. Those capabilities remain separately tracked in the [roadmap](../roadmap.md).

This change is not deployed. Production remains on the Git settings release recorded
in [October 31 deployment evidence](../testing/deployment-2026-10-31.json). Experimental
entry-format features remain disabled by default. Remote CI results are tracked in
GitHub Actions and are separate from the local checks above.

## Synthetic local-unlock probes

Added isolated Apple Secure Enclave and browser PRF experiments with generated data
only. Apple compilation/software wrapper tamper checks and Chromium virtual-authenticator
seal/reopen, cancellation, unsupported PRF and responsive UI checks passed locally.
This Mac reports Secure Enclave and Touch ID availability outside the sandbox;
physical biometric operations and device lifecycle remain untested. CI now includes
the software and virtual-authenticator checks. See the
[experiment](../../experiments/biometric-unlock/README.md) and
[evidence](../testing/biometric-unlock-2026-10-31.json).

These are development probes, not product biometric unlock or multi-device enrollment.
No production format or runtime behavior changes, real vault keys, signing credentials,
or generated secrets are included.
